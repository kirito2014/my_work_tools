### 匹配和打标机制详解

根据你最新的思路，当前实现的匹配打标机制可以分为**初始标记**、**迭代补充标记**和**层级传递标记**三个核心阶段，具体流程如下：

#### 一、初始标记阶段（第一轮匹配）
基于表B的白名单（TBL_NM）进行直接匹配：
1. **NODE_NAME匹配**：若NODE_NAME存在于表B中，该NODE_NAME对应的所有行直接标记为1（包括SOURCE_TABLE_NAME_FLAG和NODE_NAME_FLAG）。
2. **SOURCE_TABLE_NAME匹配**：若SOURCE_TABLE_NAME存在于表B中，该行SOURCE_TABLE_NAME_FLAG标记为1。
3. **未匹配项**：未命中上述条件的标记为空值（''），进入迭代补充阶段。

**示例匹配**：
- AA、AB、AD存在于表B → 直接标记为1；
- AC、AK未在表B中 → 初始标记为空。

#### 二、迭代补充标记阶段（多级下钻匹配）
以**BLOCK_NUM为分组单位**，按STATMENT_NUM顺序循环处理空标记项，核心逻辑是**“子节点驱动父节点标记”**：
1. **定位空标记项**：找出当前SOURCE_TABLE_NAME_FLAG为空的表（如AC）。
2. **下钻查找子节点**：将空标记的SOURCE_TABLE_NAME作为“父节点”，查找其作为NODE_NAME时对应的SOURCE_TABLE_NAME（即子节点）。
   - 例如AC作为NODE_NAME时，子节点为AD、AA（均标记为1）。
3. **子节点状态判断**：
   - 若子节点**全部标记为1** → 父节点（AC）标记为1；
   - 若子节点仍有空值 → 父节点保持空值，等待下一轮迭代；
   - 若子节点无数据 → 父节点维持空值。

**示例补充**：
- AC的子节点AD、AA均为1 → AC补充标记为1；
- AK的子节点AB（1）、AC（初始空→补充后1）→ AK最终标记为1。

#### 三、层级传递标记阶段（最终汇总）
完成所有迭代后，基于SOURCE_TABLE_NAME的标记结果更新NODE_NAME的最终标记：
1. **NODE_NAME汇总规则**：若某NODE_NAME下的所有SOURCE_TABLE_NAME_FLAG均为1 → 该NODE_NAME_FLAG标记为1；
2. **未完成传递**：若仍存在空标记项（无子节点或子节点未全1），则保持空值（视为未确定状态）。

**示例传递**：
- AC的子节点全1 → AC标记为1；
- AK的子节点AB、AC均为1 → AK标记为1；
- 最终所有节点完成标记传递。

#### 机制特点
1. **多轮迭代**：通过循环检测空标记项，直到无新标记产生为止，确保层级传递的完整性；
2. **细粒度分组**：按BLOCK_NUM（代码块）分组处理，避免跨代码块的无效关联；
3. **白名单向上传递**：子节点的白名单属性（标记1）可向上传递至父节点，实现“间接白名单”匹配；
4. **非侵入式标记**：仅更新空标记项，不覆盖已标记的1，保证初始匹配的优先级。

#### 关键逻辑流程
```
初始匹配 → 空标记项识别 → 子节点下钻 → 子节点状态判断 → 父节点标记更新 → 循环迭代 → 最终汇总
```

该机制通过“直接匹配+迭代下钻+层级传递”的组合，既保证了白名单的精准匹配，又通过子节点状态自动补充父节点标记，实现了从细粒度（SOURCE_TABLE）到粗粒度（NODE_NAME）的完整标记传递。
